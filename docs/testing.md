## 自动回归

```bash
mvn -B -f backend/pom.xml spotless:check test package
cd frontend
npm ci --no-audit --no-fund
npm run format:check
npm run lint
npm test
npm run build
cd ..
docker compose config --quiet
docker compose build
python3 scripts/release-check.py
git diff --check
```

后端33项：5项纯业务规则及28项HTTP/JPA集成回归，覆盖预约竞争、卡快照、课时、冻结、足额收款、退款及冲正依赖、旧会话、门店/本人/教练范围、CSV公式前缀、参数、版本及迁移映射。集成数据库H2只用于回归，不代替MySQL验收。

前端16项覆盖真实QRCode像素编码/ZXing解码、扫码生命周期、严格CSV引用与记录预览、失败后输入保留、未知写入不自动重发、动态资料范围变化、币种/日期/课时计算。构建包含完整测试，不能用跳过测试参数生成发布镜像。

## 全新MySQL验收

只在独立新建、可丢弃的空库实例运行：

```bash
TEST_URL=http://127.0.0.1:8124 python3 scripts/smoke-test.py
```

脚本检查业务为空，拒绝已有业务库。生成明确TEST档案及随机测试口令，不是公共演示种子。201项检查覆盖23表首次迁移对应的实际启动、初始化岗位、实际最后席位竞争、预留和单次码核销、卡变更及退款、原历史、整批导入回滚、实时权限、资金小数、CSV和门店汇总。私有验收状态只写忽略目录，不提交。

脚本保留一节已签到课次，等真实结束后在页面结束课次；不能通过改生产时钟伪造成功。页面验收还需验证空状态、表单错误、完整经营流程、会员及教练端、管理权限、手机窄屏、二维码图片和键盘输入。公开截图来自实际运行，不展示口令或真实客户资料。

## 持久化与发布

在独立测试项目核对重启前后业务、资金原单、课时及岗位；备份到私有目录，恢复到独立新卷，再核对同样数据与迁移。保存内部证据，不把数据备份、会话或测试口令发布。发布检查只扫描自有源码与公开资料，核对两原中文二维码、英文联系方式、链接、六类以上截图、许可和敏感信息。

实体数据库和二维码像素可自动核验，但此版本没有实测具体物理摄像头型号、USB扫码枪、门禁或支付硬件；浏览器图片识别和输入测试不能宣称替代这些现场设备验收。部署方应按设备、HTTPS环境与本店规则另验收。
