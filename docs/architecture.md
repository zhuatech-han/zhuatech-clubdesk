# ClubDesk 架构与数据库

知华科技（上海如静知华信息科技有限公司） · [官网](https://www.zhuatech.cn/) · 微信 zhuatech、zhuatech2；源码非商业使用，以 LICENSE 为准。

Vue 3通过同源Nginx调用Spring Boot，后端使用Spring Security认证、JPA事务及Flyway迁移访问MySQL 8.4。浏览器不保存业务假数据，列表、状态、余额与权限由服务器返回。相同前端按当前角色分别展示门店、教练及会员入口。

## 模块职责

- `AuthController`、`SecurityConfig`：会话、CSRF、密码散列、失败限制和旧凭据失效。
- `AccessService`、`AdminService`：实时岗位权限、ALL/DEPARTMENT/MEMBER/TRAINER资料范围、档案绑定、最后管理员及内建资源保护。
- `MasterService`：会员、教练、教室、课程、套餐，引用/版本校验，整批会员导入。
- `ClubService`、`ClubPolicy`：卡约定、排课、抢位、预留、出勤、二维码、退款和历史。
- `ReadService`：范围过滤的工作台、本人业务、详情、报表及CSV。教练读取不返回联系备注、会员资金和他人名单。
- `Store`：持久化、有限读取和显式锁；单类最多读取10000条。前端每页10条，不是服务端海量分页。

## 表与关系

[V1迁移](../backend/src/main/resources/db/migration/V1__club_schema.sql)包含22张应用表，另有Flyway历史表。账号、角色、权限、菜单、门店、参数、字典和审计构成管理能力；会员、教练、教室、课程、套餐、会员卡、课次、预约、资金流水、课时流水、业务事件、短码散列和到店记录构成业务能力。

会员/教练账号绑定其档案，不可转换成员工。会员、教练、卡、课程与课次保留所属门店。账号和业务关联有外键；同会员同课次、资金外部编号等有唯一约束。资料删除被引用时拒绝；停用不删除历史。

卡保存套餐价格、次数、时长和币种快照；课次保存时长、名额和取消期限。后续目录编辑不改已售卡或发布课次的约定。资金用BigDecimal及DECIMAL两位小数，不能截断。课时流水分别记录总次数、预留和已使用变化，余额能与原始流水复算。

## 一致性与时间

写事务采用READ_COMMITTED，并锁基础门店记录串行化实例写入。预约的卡余额、名额、版本、门店、时间重叠和唯一会员课次规则在一个事务核验；追加流水和业务变化共同提交或回滚。前端不自动重复未知结果的写入。这适合小型场馆，不宣称分布式高吞吐。

用户输入门店本地时间，通过IANA时区转换为Instant；不存在或重复的夏令时本地时间被拒绝。卡有效期以门店日期为准，需覆盖整节课；报表以每个门店日期分组。业务已创建后门店时区锁定，避免历史语义改变。

动态码为24字节随机数的编码，2分钟有效且单次使用；数据库仅存SHA-256。刷新使旧码作废。未成功核验课次或门店权限时不消费码，成功核验及课时扣减原子提交。动态码不是身份证明或门禁钥匙。

## 迁移与演进

JPA使用`ddl-auto=validate`，Flyway负责结构；不可修改已经执行的V1。升级增加V2及以后版本，先备份，在独立测试卷恢复并验证登录、卡约定、余额、资金原单及权限。多公司隔离、跨店共享权益、服务端分页、门禁或支付需要明确业务设计和专项验收，不是已完成集成。
